## 2. 発見1 — 営業CRMシートが本番に存在しない【監査の訂正】

**`CATERING_SALES_TARGETS` と `CATERING_SALES_DASHBOARD` はワークブックに存在しない。**

`repo-audit.md` §2 で「集客先CRMは `CATERING_SALES_TARGETS` を再利用できる（★★★）」と書いたが、
正確には **コード（`core/catering_sales.py`）は存在するが、本番シートは未作成**だった。
`/catering-sales-setup` が本番で一度も実行されていない。

同様に、他システムのシートも本ワークブックには無い（`LEAD_MASTER` / `PROJECT_PROFIT` /
`REVIEW_REQUEST_MASTER` 等）。これらは中央ハブ（`GOOGLE_SPREADSHEET_ID`）側にあるか、未作成。

### 計画への影響

`sheet-schema.md` §2-1 の「既存22列の右端に11列追加」は、**そのままでは実行できない**。
先に**シートを作る工程**（`/catering-sales-setup` の実行）が必要。

ただしこれは**既存コードを1回実行するだけでコード変更ゼロ**。
むしろ**シート新規作成なら、最初から33列のヘッダで作れる**ので、列追加マイグレーション（W1-5）が
不要になり、工程が減る。

## 5. この数字から読めること

### 5-1. 売上の41%が単一商品ライン1件に依存している

`オーダー弁当 ¥211,500 / 数量1`。**この1件を除くと半年で ¥296,399、月平均約¥59,000**。
実質は月5〜6万円規模の商売になっている。

**この1件の発注元を特定して再受注させることが、現時点で判明している中で最も投資効率の高い打ち手。**
月間目標 ¥800,000 に対して単独で 26% を占める。新規10件を取るより速い。

### 5-2. 課題は「問い合わせが少ない」ではなく「件数が絶対的に足りない」

月の会計件数が 1〜6 件。仕様書の30日目標「問い合わせ15件・受注3〜5件」は、
**現状の実績（月2〜6件）に対して2〜3倍を狙う設定**であり、妥当だが楽ではない。

### 5-3. リピートしているかどうかが判定不能

`06_売上管理` が月次合計（`企業名` = `Airmate月次集計` / `受注番号` = `AUTO`）でしか
記録されていないため、**14件が「14社」なのか「3社の繰り返し」なのか分からない**。

`05_顧客台帳` が空なので、LTV（顧客生涯価値）も再来店率も算出できない。
**これは集客OS以前の、記録の欠落。** 今後の案件から企業別に記録し始める必要がある。

### 5-4. 過去の流入元は永久に遡れない

売上が月次合計なので、企業別・流入元別に分解する材料が存在しない。
**「どのチャネルが儲かったか」は、これから記録する案件からしか出せない。**

→ `GROWTH_DASHBOARD`（W1-9）が意味のある数字を返し始めるのは、
**記録開始後に受注が数件積み上がってから**（最短で3〜4週目）。
それ以前は「接触数・返信数」までしか見えない。この期待値をオーナーと共有しておく。

### 5-5. 粗利の実績データが存在しない

`07_利益管理` は setup が書いたサンプル1行のみ（売上¥100,000 / 粗利¥50,000 / 粗利率50%）。
**これは実績ではなくデモ値。** `configs` 側の Catering 目標粗利率 50% も目標であって実績ではない。

→ **粗利率50%が現実的かどうか、実績で検証されていない。** 案件を記録し始めて初めて分かる。

### 5-6. コンテンツ配信は動いている

`08`〜`11` に90日分の投稿が入り、シート15の実行ログは 2026/06/20 以降の配信を記録している。
初回3件は `LINE送信 ❌` だが、08:23 以降は `✅`。**コンテンツ供給側は稼働済み。**

つまり**足りないのは発信ではなく、受け皿（CRM）と記録**である。

## 6. 計画の修正

### 6-1. 立ち上げ順の入れ替え

`operations-sop.md` §4 の Step 1（CSV100件）より前に、**オーナーにしかできない2件**を置く。

| 順 | やること | 担当 | 理由 |
|---|---|---|---|
| **1** | **¥211,500 のオーダー弁当の発注元を特定** | オーナー | 単独で月目標の26%。最速の売上回復 |
| **2** | 過去14件の取引先を可能な範囲で書き出す | オーナー＋スタッフ | `05_顧客台帳` が空。Airmate 明細・LINE・請求書控えから |

| 4 | 列追加（危険度 中→低） | 機械 | 3 で33列で作れば W1-5 は不要になる |
| 5 | CSV 100件投入 / UTM / 次アクション / ダッシュボード | 機械＋スタッフ | 予定どおり |

### 6-2. W1-5 の位置づけ変更

CRM シートを最初から33列で作れば、**W1-5（CRM列拡張マイグレーション）は不要**。
ただし `ensure_columns()` 自体は `02_問い合わせ` 等の既存シート（W1-6）で必要なので実装は残す。

### 6-3. 期待値の調整

| 項目 | 当初の想定 | 実地調査後 |
|---|---|---|
