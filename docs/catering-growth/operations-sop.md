## 0. この文書の目的

仕様書には「**ゆうさん本人の運用作業: 週30分以内**」と書かれています。これは「頑張って時短する」では絶対に達成できません。**役割を先に分けて、ゆうさんの手元に判断だけが届く形に作り込む**必要があります。

この文書は、誰が何を何分やるかを決めるものです。

- ❌ DMを書く・送る

これらは全部、テンプレート・機械・スタッフの側に寄せます。**ゆうさんに届くのは「はい/いいえ」で答えられる判断だけ**です。

## 2. ゆうさんの1日 — LINEに届くものだけ見る

既存の仕組み（`core/owner_daily.py`）がすでにこの形になっているので、そこに乗せます。**新しいアプリもチャットも増やしません。**

毎朝9時、LINEにこういう形で届きます:

```
【TREE's Catering 集客OS】8/12(火)

■ 承認をお願いします（2件）
1. 提携申込: レンタルスペースA（那覇・50名収容）
   → 掲載条件: 手数料なし・相互紹介
   返信: OK 1 / NG 1

2. 値引き申請: B社 懇親会 40名
   → 通常12万 → 10.5万（粗利率52%→45%）
   返信: OK 2 / NG 2

■ 今週の数字
受注 2件 / 売上 24万 / 粗利 11.5万（粗利率48%）
一番効いた流入元: 過去顧客（受注2件・粗利11.5万）
反応ゼロの施策: Instagramストーリー（接触18・返信0）

■ 判断が必要なこと（1件）
提携先C（BAR）は掲載30日で問い合わせゼロ。
継続しますか？ → 返信: 継続 C / 停止 C
```

**返信は「OK 1」のような2文字で済みます。** 既存の返信コマンド機構（`core/owner_daily.py`）をそのまま使います。

## 3. スタッフの1日 — 20分で終わる形

毎朝9時、スタッフのLINEに「今日やること」が届きます（既存の `core/daily_action_commander.py` に相乗り。**新しい配信は作りません**）。

```
【今日の集客タスク】8/12(火)

▼ 今日 初回連絡する（3件）
1. レンタルスペースD 担当:山田様
   → スプレッドシート tc_0051 行の「完成文」をコピーしてInstagram DMで送信
2. …

▼ 3日フォロー（2件）
▼ 7日フォロー（1件）
▼ 返信あり・未対応（1件）★最優先
▼ 見積出して48時間経過（1件）
▼ 受注後の口コミ依頼（1件）
```

### スタッフの作業手順（1件30秒）

1. スプレッドシート `CATERING_SALES_TARGETS` を開く
2. 指示された行（例: `tc_0051`）の **`営業文` 列のセルをコピー**
   - 相手の名前・担当者名・UTM付きURLが**すでに差し込まれた完成文**が入っています
3. Instagram DM / LINE / メールに貼って送信
4. その行の `ステータス` を `CONTACTED` に変更、`最終接触日` に今日の日付を入れる

**文章を書く作業はゼロです。** コピーして貼るだけです。

### Step 2: CSVを投入（スタッフ・10分）

```
1. まず dry-run で確認     → 「取込予定100件 / エラー3件 / 重複2件」が行番号つきで出る
   POST /catering-import-contacts   （本文に CSV。dry-run が既定で1セルも書かない）
2. エラー行の理由を見て直す  → 例: 流入元コードのスペルミス、優先度が A/B/C 以外

```

**1行の不備で全体が止まりません。** ダメな行だけ理由つきで返るので、そこだけ直して再投入します。

⚠️ **数字にカンマを入れるときは注意。** `200,000` のようにカンマを入れると CSV の列が
割れます。表計算ソフトからCSV書き出しすれば自動で `"200,000"` と引用符が付くので問題
ありませんが、手でCSVを書く場合は**カンマなし（`200000`）**にしてください。
列が割れた行は取り込まれず、理由つきで reject されます（黙って壊れません）。

## 5. 月1回の判断会（ゆうさん・15分）

`GROWTH_DASHBOARD` を見て、次の3つだけ決めます。

### 判断1: 伸ばす施策はどれか

**流入元を「粗利」で並べます。問い合わせ件数では並べません。**

| 流入元 | 接触 | 問い合わせ | 受注 | 売上 | **粗利** | 判断 |
|---|---|---|---|---|---|---|
| 過去顧客 | 20 | 6 | 3 | 36万 | **17万** | ⬆ 増やす |
| 紹介 | 8 | 4 | 2 | 26万 | **13万** | ⬆ 増やす |
| 提携BAR | 15 | 3 | 1 | 8万 | **3万** | → 様子見 |
| Instagram | 40 | 2 | 0 | 0 | **0** | ⬇ 減らす |

この例だと、**Instagramに40件も手をかけて粗利ゼロ**。過去顧客は20件の接触で17万。**同じ労力なら過去顧客に寄せるべき**と判断できます。

> 件数で見ると「Instagramは接触40件で一番多い」と見えてしまいます。**粗利で見ないと、忙しいだけで儲からない施策に時間を吸われます。**

### 判断2: 止める施策はどれか

**2ヶ月連続で粗利ゼロの流入元は止めます。** 迷ったら止めて、空いた時間を1位の施策に足します。

### 判断3: 失注理由が偏っていないか

| 失注理由が多い | 意味 | 打ち手 |
|---|---|---|
| `price`（予算が合わない） | 値段が高い or 安い客層に当てている | 低単価オードブル商品を出す／狙う層を変える |
| `date_unavailable`（日程が埋まっていた） | **売れている。キャパの問題** | 人員・提携先への振り分けを考える。**値上げの検討も** |
| `menu_mismatch`（料理が希望と違う） | 商品ラインが足りない | メニュー幅を増やす |
| `no_response`（連絡が途絶えた） | フォローのタイミングが悪い | フォロー回数・文面を変える |

**`price` と `date_unavailable` は打ち手が正反対です。** 前者は安くする方向、後者は値上げの方向。記録していないとここを間違えます。

## 6. 事故を防ぐルール（守らないと壊れるもの）

| ルール | 理由 |
|---|---|
| **`core/catering_setup.py` は二度と実行しない** | ヘッダ行を上書きし、追加した列を消す |
| **スプレッドシートの列を手で挿入・並べ替え・改名しない** | プログラムが列の位置で読んでいる。週次レポートの数字が静かに壊れる |
| **列を足すときは必ず版履歴で復元ポイントを作ってから** | 戻せなくなる |
| **列を足したら `/catering-weekly` の受注率・粗利率が変わっていないか確認** | 変わっていたら列がズレている |
| **一度振ったIDは変えない・使い回さない** | 過去の売上との紐付けが切れる |
| **顧客CSVをリポジトリにコミットしない** | 個人情報の公開事故 |
| **`流入元コード` を空欄にしない** | 「未入力」と「該当なし」の区別がつかず集計が壊れる |
| **公開許可のない写真・顧客名を投稿に使わない** | 信用の問題。既存の写真承認チェックリストを使う |
| **自動DM・自動投稿を有効にしない** | 仕様書 §8 で禁止。アカウント停止リスク |

## 7. 30日後に「成功」と言える状態

仕様書 §7 の目標を、確認できる形に落とします。

| 項目 | 目標 | どこで確認するか |
|---|---|---|
| 連絡先の登録 | 100件 | `CATERING_SALES_TARGETS` の行数 |
| 提携候補への接触 | 30社 | `種別` が `partner_*` かつ `ステータス` が `CONTACTED` 以上 |
| 提携掲載 | 5社 | `ステータス` = `PARTNER_LISTED` |
| 口コミ獲得 | 10件 | `12_口コミ` / `REVIEW_DASHBOARD` |
| 問い合わせ | 15件 | `02_問い合わせ` の行数 |
| 受注 | 3〜5件 | `04_受注管理` の `受注状況` = 受注 |
| LP経由売上 | 30〜50万円 | `GROWTH_DASHBOARD` の `売上`（`other` 以外の合計） |
| **粗利** | **売上の45%以上** | `GROWTH_DASHBOARD` の `粗利` |
| ゆうさんの作業時間 | 週30分以内 | 承認件数 × 2分 で概算 |

### 30日後に必ず確認すること

**「結合できなかった件数」がどれくらいあるか。** ここが多いと、上の数字は「一部しか見えていない数字」です。

例: 受注5件のうち3件しか流入元が紐付いていなければ、「どの施策が効いたか」の結論は**まだ出せません**。その場合は数字で判断せず、まず入力の抜けを直します。

数字を信じてよいのは、**紐付け率が8割を超えてから**です。
